# POS 이벤트 메뉴 설정과 메뉴 영구 삭제

기존 POS 설정에서는 엽전 가격을 바꿀 수 없고 판매 체크를 해제하면 품절로만 표시됐다. 메뉴 편집에서 이벤트 주문 허용 여부와 엽전 가격을 저장하고, 별도 확인 후 메뉴를 DB에서 영구 삭제할 수 있도록 변경한다.

## 변경 동작

- `POS → 설정 → 메뉴와 가격`에서 `이벤트 주문 허용`을 켜고 `엽전 가격`을 입력한 뒤 저장한다. 가격은 1 이상의 정수만 허용한다.
- 이벤트 주문을 해제하면 일반 주문 가격은 유지하며 새 엽전 주문만 차단한다. 이미 접수한 주문의 엽전 가격과 수령 기록은 변경하지 않는다.
- `판매 중`을 해제하면 기존처럼 품절 처리한다. `메뉴 영구 삭제`는 확인창을 거쳐 카탈로그 행을 실제 삭제하며 고객·POS 메뉴 목록에서 제거한다.
- 삭제된 메뉴의 주문 내역, 수량, 금액, 엽전 수령·서빙·결제 및 판매 통계는 유지한다. 삭제한 ID는 재사용할 수 없으며 새 메뉴는 새 ID로 추가한다.

## API·DB

- 관리자 snapshot의 메뉴에 `coinPrice: number | null`을 포함한다.
- `PUT /api/v1/admin/menus/{id}`는 양의 정수 `coinPrice`로 이벤트 주문을 허용하고 `null`로 해제한다. 필드를 생략하는 구버전 요청은 기존 값을 유지한다. 소수·음수·0·정수 범위 초과를 거부한다.
- `DELETE /api/v1/admin/menus/{id}`는 기존 직원 인증을 요구한다. 삭제 감사 기록과 메뉴 변경 SSE를 남기며 없는 메뉴에는 404를 반환한다.
- V8은 기존 주문 항목에 카테고리 스냅샷을 채우고 메뉴 외래 키를 제거한다. 주문의 원래 메뉴 ID와 이름·금액 스냅샷은 유지한다. 새 주문도 카테고리 스냅샷을 저장한다.
- 통계는 메뉴가 삭제되면 주문 스냅샷을 사용한다. 주문 생성과 메뉴 저장·삭제는 같은 트랜잭션 잠금으로 직렬화한다.

## 검증

- Java 21 / PostgreSQL Testcontainers 통합 테스트 33개 통과.
- 이벤트 가격 설정·잘못된 가격 거부·생략 호환성·이벤트 해제 이후 일반 주문 유지 확인.
- 실제 메뉴 행 삭제, 고객 목록 제거, 주문/판매 통계 유지, 삭제 이후 엽전 수령·서빙·원화 결제 확인.
- V6 주문 데이터를 최신 마이그레이션으로 이행한 뒤 메뉴를 삭제해도 기존 수량·금액이 유지됨을 확인.
- 프런트엔드 테스트 18개, ESLint, TypeScript/Vite 빌드 통과. 빌드는 검증용 로컬 API 주소를 지정했다.
- 로컬 모의 API에 연결한 브라우저에서 이벤트 가격 저장·새로고침 유지·비활성화·0개 저장 차단과 메뉴 편집 레이아웃 확인. 실제 삭제 동작은 백엔드 통합 테스트로 검증했다.

운영 배포·운영 DB 마이그레이션·실제 메뉴 삭제는 실행하지 않았다. 배포 시 V8과 새 백엔드를 적용한 후 새 프런트엔드를 적용한다.
