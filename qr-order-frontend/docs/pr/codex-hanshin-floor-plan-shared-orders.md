# 개요

소프트 한신포차의 4인 단위 T01~T24 좌석 배치를 테이블 선택 화면에 적용했다.
합석하면 고객 QR과 스태프 상세에서 현재 방문 그룹의 기존·추가 주문을 함께 보고,
분리하면 접수된 방문별 주문내역으로 돌아간다.

## 변경 사항

- `hanshinFloorPlan.ts`를 공통 좌표로 사용하고 `TableFloorPlan`에서 원형·사각형·마름모를 표시한다.
  카운터 기준 점대칭으로 T19·T18·T17이 오른쪽 위에 오며 글자는 정방향이다.
- 홈과 테이블 작업 화면의 배경, 이동 및 합치기 창에 같은 24개 테이블을 표시한다.
  단체석 자동 합석은 없으며 실제 선택 가능 여부는 API의 테이블 등록·사용 상태를 따른다.
- Spring Boot `TableOrderScope`가 현재 방문 그룹을 해석한다. 고객 목록·단건 조회 모두 같은
  범위를 검사하므로 다른 그룹이나 종료된 방문의 주문 번호를 알아도 조회할 수 없다.
- 주문 ID와 접수 테이블·세션을 보존한다. 고객 내역에는 합석 그룹 및 접수 테이블을,
  스태프 상세에는 접수 테이블과 그룹 공통 주문을 표시한다.
- 기존 그룹에 사용 중인 독립 테이블을 하나씩 추가해 12인 이상 단체도 처리한다.
  다른 합석 그룹을 중첩하는 동작과 중복 합석은 거절한다.
- 그룹 전체 금액을 반복하던 분리 미리보기를 실제 구성 방문의 건수·금액으로 고쳤고,
  홈의 그룹별 미처리 품목 중복 합산을 제거했다.
- 주문 생성·서비스·수정·조리 상태 변경 이벤트를 그룹 QR마다 저장해 실시간 SSE와
  재연결 replay에 모두 반영한다. 합석 해제 직전의 오래된 HTTP 응답은 무시한다.

## 검증

- 프론트엔드 Vitest 6개 테스트 통과: 24개 독립 4인 좌석, 오른쪽 위 T17~T19,
  미등록 번호 비활성 및 추가 등록 테이블 유지, 합석 미처리 중복 방지, 고객 접수 테이블 표시.
- `npm run lint` 및 `VITE_API_BASE_URL=http://localhost:8080 npm run build` 통과.
- Java 21, Testcontainers PostgreSQL에서 `./gradlew test` 18개 테스트 통과.
  현재/과거 방문 격리, 3개 테이블 합석, 합석 전후 주문, 서비스·수량·취소·조리 변경,
  SSE replay, 분리 및 결제, 이동 전 QR 조회와 갱신을 검증한다.
- 브라우저 1194×834: 홈, 상세, 합치기, 이동 배치 및 선택 가능/불가능 상태 확인.
- 고객 주문내역 390×844와 320×740: 합석 안내, 접수 테이블, 합계 표시와 가로 넘침 없음 확인.
  고객 화면은 로컬 고정 데이터로 시각 검증하고 실제 조회·변경 동작은 서버 통합 테스트로 검증했다.

## 참고 사항

- 운영 API/DB 배포는 별도다. 실제 사용 전 관리 설정에 T01~T24를 등록·활성화하고 QR을 발급해야 한다.
  미등록 테이블은 클릭할 수 없으며 기존 QR/토큰은 자동 변경하지 않는다.
- 합치기 창은 iPad에서 배치와 정책 안내를 동시에 읽을 수 있도록 반복되는 배치 제목·푸터를
  숨기고, 합친 결과는 선택 안내줄에 표시한다. 터치 크기 유지를 위해 작은 화면에서는 내부 스크롤을 허용한다.
- 결제에는 기존 대표 테이블의 할인율을 적용하고 분리 후에는 각 방문의 할인율을 유지한다.
  장바구니는 기기별로 유지하며 공유하지 않는다. 빈 테이블은 주문 접수 후 합칠 수 있다.
- 현재 작업 체크아웃 `dev`에서 `codex/hanshin-floor-plan-shared-orders`로 분기했다.
