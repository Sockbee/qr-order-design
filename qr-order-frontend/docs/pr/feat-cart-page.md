# 개요

Figma `ui-ux` 파일의 **S05 — Cart**(장바구니) 화면을 구현했습니다.
뒤로가기 앱바, 옵션 요약과 라인별 수량 스테퍼가 있는 장바구니 라인 목록,
"메뉴 더 담기" 버튼, 총 결제금액, 그리고 하단 고정 주문 바로 구성됩니다.

**부가세는 받지 않습니다** (2026-08-25 결정, `UX-STRUCTURE.md` §3 S05).
메뉴 가격이 최종 가격이므로 breakdown은 총 결제금액 한 줄로 끝나고,
S02·S05의 주문 바 금액은 라인 합계와 동일합니다.

### 수정한 컴포넌트

- `Button` — `large` 사이즈의 폰트를 `--type-body-strong`(16/700/24)에서
  신규 `--type-label-button-m`(15/700/22)으로 교정했습니다. 이 프레임의
  Large/Weak 버튼이 `Label/Button-M` 텍스트 스타일을 쓴다는 사실이 이번에
  처음 드러났습니다. S02·S04는 Large 버튼을 쓰지 않아 영향이 없습니다.
- `QuantitySelector` — `ariaLabel` prop 추가. S04는 "수량" 라벨 요소를
  `labelledBy`로 가리키지만, S05는 라인마다 스테퍼가 있어 가리킬 라벨 요소가
  없습니다. "김치찌개 수량"처럼 라인별 접근성 이름을 부여합니다.

### 지원 파일

  - `calculateCartTotal(lines)` → `number`
  - `describeCartLineOptions(item, line)` → `"보통 · 공기밥 추가"`

### 교차 화면 정합

S05 프레임을 보기 전에는 S02 하단바의 금액이 어떤 값인지 확정할 수
없었습니다. S05가 총 결제금액을 명시하면서 **두 화면이 같은 값을 그린다**는
것이 확인되었습니다. 이를 맞추기 위해:

- `MenuPage` 하단바가 `calculateCartTotal()`을 쓰도록 변경했습니다.
  라인 합계 계산이 두 화면에 중복되지 않습니다.
- 목 장바구니를 S05 프레임과 동일하게 재구성했습니다.
  김치찌개(보통 · 공기밥 추가) 10,000 + 제육볶음(보통) 13,000 = 총 23,000.
- 이에 맞춰 제육볶음의 옵션 그룹을 S04 때 임의로 만들었던 "양 선택"에서
  "맵기 선택"(필수, 기본값 보통)으로 교체했습니다. 프레임의 라인 요약 "보통"이
  실제 데이터에서 나오게 됩니다.

결과적으로 **하나의 목 데이터로 S02와 S05 프레임의 숫자가 동시에 일치**합니다.

기본값 없는 필수 그룹(담기 비활성화)의 사례는 비빔밥 "고추장 선택"에 그대로
남아 있어, S04의 검증 로직은 여전히 확인 가능합니다.

### 화면 연결

- `src/App.tsx` — `screen`에 `'cart'` 추가, 라인 수량 변경 핸들러 추가.
- `src/pages/MenuPage.tsx` — `onOpenCart` prop 추가. 앱바 장바구니 칩과 하단

여전히 `App.tsx`의 로컬 상태 기반이며 실제 라우팅의 임시 대체물입니다.

반환값이 단일 숫자를 돌려주는 `calculateCartTotal`로 대체되었습니다.

## 참고 사항

**의도적인 차이**

- **PriceBreakdown / BottomOrderBar가 1px 큼.** Figma는 inside stroke라
  구분선이 높이에 포함되지만, CSS `border-top`은 1px을 더합니다. 요소의 시작
  좌표는 프레임과 일치하며 누적되지 않습니다. S04 옵션 행처럼 `outline`으로
  치환하는 방법은 한 변만 그릴 수 없어 적용하지 않았습니다.
- **`calculateCartTotal`은 단일 숫자를 반환합니다.** 부가세가 없어진 지금
  `{ subtotal, total }` 형태는 두 값이 항상 같아 의미가 없습니다. 서비스 요금이나
  최소 주문금액 미달 같은 항목이 실제로 도입될 때 구조를 다시 넓히는 편이
  낫다고 판단했습니다 (`CLAUDE.md` — 선행 추상화 지양).

**한계 / 후속 작업**

- **라인 삭제가 없습니다.** 수량 최소값은 1이고 감소 버튼이 비활성화됩니다
  (`ext/QtyStepper` 계약). 삭제는 D1 확인 다이얼로그와 함께 들어와야 합니다
  (UX-STRUCTURE §2.2). `ext/Dialog`는 아직 없습니다.
- **빈 장바구니 상태는 아직 도달 불가.** 삭제 수단이 없어서 코드 경로만
  존재합니다(방어적 fallback + 하단바 비활성). `ext/EmptyState`(§5.5)로
  교체되어야 합니다.
- 주문하기는 아직 no-op입니다. S06 주문 확인 화면이 다음 단계입니다.
- 최소 주문금액 미달(below-minimum), updating, line-unavailable 상태(§5.5)와
  주방 요청사항 `tds/TextField`(§3 S05 rank 6)는 프레임에 없어 범위 밖입니다.
- 장바구니는 여전히 메모리 상태이며 `localStorage` 영속화(§6.2)는 미구현입니다.
