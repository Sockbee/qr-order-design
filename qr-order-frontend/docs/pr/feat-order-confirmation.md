# 개요

Figma `ui-ux` 파일의 **S06 — Order Confirmation**(주문 확인)과
**S07 — Order Complete**(주문 확정) 두 화면을 구현했습니다. 주문 흐름의
마지막 두 단계가 하나의 전환으로 이어지므로 같은 PR로 묶었습니다.

- **S06** — 테이블 번호를 다시 보여주고, 읽기 전용 주문 요약과 총 결제금액,
  후불 결제 안내, 그리고 "주문 확정" CTA를 제공합니다. 되돌릴 수 없는
  마지막 지점이므로 화면 자체는 편집을 제공하지 않고 "수정하기"로 S05에
  돌려보냅니다 (DESIGN.md §12.5).
- **S07** — 접수 확인 마크, 테이블 안내 문구, 제품 전체에서 유일한
  Display/Total(36/700) 금액, 주문번호를 보여주고 "주문 현황 보기"와
  "추가 주문"으로 이어집니다.

## 변경 사항

### 화면

- `src/pages/OrderConfirmationPage.tsx` / `.css` — S06.
- `src/pages/OrderCompletePage.tsx` / `.css` — S07.

### 재사용한 컴포넌트

새로 만든 컴포넌트는 없습니다. 두 프레임이 요구하는 요소가 기존 컴포넌트로
모두 커버되었습니다.

- `TableChip` — S06의 `ext/TableChip`(16:85)은 S01과 지오메트리가 동일합니다.
- `PriceBreakdown` — S06의 `TotalRow`(16:94)는 S05의 `ext/PriceBreakdown`과
  구조·간격·타이포가 완전히 같습니다(상단 구분선 + `pt16` + 22/700 한 행).
  별도 컴포넌트를 만들지 않고 그대로 재사용했습니다.
- `AppBar`(뒤로가기 + 타이틀), `Button`(Medium/Weak, Large/Weak, XLarge/Fill).

S06의 요약 행과 S07의 확인 마크는 각 화면에서만 쓰이므로 페이지 안에
두었습니다 (`CLAUDE.md` — 1회성 컴포넌트 과다 추상화 지양).

### 수정한 컴포넌트

- `Button` — `medium` 사이즈의 폰트를 `--type-caption-strong`(14/700/21)에서
  `--type-label-button-m`(15/700/22)으로 교정했습니다. S06의 "수정하기"가
  Medium 버튼을 처음 사용하면서 드러났습니다. 앞서 `large`에서 잡은 것과
  같은 성격의 불일치입니다. 다른 화면은 Medium을 쓰지 않아 영향이 없습니다.

### 지원 파일

- `src/types/order.ts` — 신규. `PlacedOrder { number, tableNumber, lines, total }`.

### 추가한 디자인 토큰

- `--type-display-total: 700 36px / 54px` (Figma `Display/Total`).
  UX-STRUCTURE §3 S07이 "제품 내 유일한 H1"로 규정한 금액 전용 토큰입니다.

### 화면 연결

- `src/App.tsx` — `screen`에 `'confirm'`, `'complete'` 추가.
  - S05 주문하기 → S06
  - S06 뒤로가기 / 수정하기 → S05
  - S06 주문 확정 → 주문 생성, 장바구니 비움, S07
  - S07 추가 주문 → S02
  - S07 주문 현황 보기 → no-op (S08 미구현)
- 주문은 `orders: PlacedOrder[]`로 누적하며 주문번호는 `A-1042`부터
  순번이 올라갑니다. 한 세션에서 여러 번 주문하는 것이 정상 흐름이기
  때문입니다 (UX-STRUCTURE A3). S08이 이 배열을 그대로 쓰게 됩니다.
- 주문 확정 시 장바구니를 비웁니다. 다음 주문은 새로운 라운드입니다.

여전히 `App.tsx`의 로컬 상태 기반이며 실제 라우팅의 임시 대체물입니다.

## 참고 사항

**의도적인 차이**

- **주문 요약을 `CartLine`으로 만들지 않았습니다.** UX-STRUCTURE §3 S06 rank 3은
  "비상호작용 `ext/CartLine`"으로 적고 있으나, 프레임이 그리는 것은 썸네일도
  스테퍼도 없는 "이름 × 수량 / 금액" 한 줄입니다. `CLAUDE.md`가 Figma를
  우선하므로 프레임을 따랐습니다.
- **안내 문구의 줄바꿈.** S07 문구는 프레임에 두 줄로 작성되어 있습니다.
  컨테이너 폭에 의존한 자동 줄바꿈 대신 두 개의 블록 `span`으로 나눠 번역
  시에도 의도한 분리가 유지되도록 했습니다.
- **Mark의 라디우스를 `50%`로 지정.** 프레임은 64px 박스에 32px 라디우스로,
  결과가 정확히 원입니다. 크기가 바뀌어도 원을 유지하도록 `50%`를 썼습니다.
- **TotalRow / Footer가 1px 큼.** Figma는 inside stroke, CSS `border-top`은
  1px을 더합니다. 요소의 시작 좌표는 일치하며 누적되지 않습니다.

**한계 / 후속 작업**

- **PLACING 로딩 상태 미적용.** UX-STRUCTURE §5.2는 주문 확정 버튼이 로딩
  상태(너비 유지)로 바뀌고 화면 입력이 잠겨야 한다고 규정합니다. `Button`에
  `loading`이 이미 구현되어 있지만, 호출할 API가 없는 상태에서 가짜 지연을
  넣는 것은 없는 동작을 지어내는 일이라 연동 시점으로 미뤘습니다.
- **S07 자동 전환 미적용.** §3 S07의 "4초 후 S08 자동 이동, 탭하면 취소"는
  S08이 없어 구현하지 않았습니다. "주문 현황 보기"도 현재 no-op입니다.
- 주문 실패 경로(E4 네트워크 실패, E5 주방 거절)와 D3 이탈 경고는 범위 밖입니다.
- 주문 내역은 메모리 상태이며 `localStorage` 영속화(§6.2)는 미구현입니다.
  새로고침하면 주문번호가 A-1042부터 다시 시작합니다.
