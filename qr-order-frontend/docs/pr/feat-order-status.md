# 개요

Figma `ui-ux` 파일의 **S08 — Order Status**(주문 현황) 화면을 구현했습니다.
현재 진행 상태를 나타내는 4개 칩, 주문 회차별 내역(최신순), 세션 누적 합계,
그리고 "추가 주문"·"직원 호출" 버튼으로 구성됩니다.

한 자리에서 2~4회 주문하는 것이 정상 흐름이므로(UX-STRUCTURE A3), 이 화면은
세션의 모든 회차를 누적해서 보여줍니다. 뒤로가기가 없는 것도 의도된 것으로,
탭을 잃었을 때 QR을 다시 스캔해 돌아오는 복구 지점이기 때문입니다 (§3 S08).

## 참고 사항

**의도적인 차이**

- **`SessionTotal`을 `PriceBreakdown`으로 재사용하지 않았습니다.**
  타이포(22/700)와 구조는 같지만 `PriceBreakdown`은 상단 구분선과 `pt16`을
  자기 정체성으로 갖고 있고, S08의 합계 행에는 둘 다 없습니다. 구분선을
  옵션으로 빼서 설정 가능한 컴포넌트로 만드는 것보다 두 줄짜리 마크업을
  페이지에 두는 편이 낫다고 판단했습니다.
- **`OrderRound`가 2px 큼.** Figma는 inside stroke라 상하 구분선이 높이에
  포함되지만 CSS `border`는 각각 1px씩 더합니다. 요소의 시작 좌표는
  일치합니다. 회차가 늘어나면 회차당 2px씩 누적되지만, 회차 사이는 24px
  간격으로 떨어져 있어 구분선이 겹쳐 보이지는 않습니다.
- **`text/muted`를 예정 단계 칩에 사용.** 접근성 규칙상 muted는 가격·알레르기·
  판매 여부를 전달할 수 없지만, 예정 단계 칩은 그런 정보를 담지 않습니다.
  프레임과 UX-STRUCTURE §5.4가 모두 이 색을 규정합니다.

**목 데이터에 대한 정직한 고지**

- **주문 상태를 `preparing`으로 고정 생성합니다.** 실제로는 서버 폴링으로
  내려와야 하는 값입니다(§5.4, 15초 주기). 폴링할 API가 없는 상태에서
  S08 프레임이 "조리 중"을 현재 단계로 그리고 있어 프레임과 맞추고 칩 3가지
  상태를 모두 확인할 수 있도록 이 값을 썼습니다. 갓 접수된 주문의 의미상
  올바른 값은 `accepted`이며, 연동 시 서버 값으로 대체되어야 합니다.
- **회차 시각은 실제 주문 시각**이라 프레임의 "오후 7:24"와는 다릅니다.

**한계 / 후속 작업**

- **폴링 미구현.** §5.4의 15초 주기 갱신과, 폴링 실패 시 마지막 상태를 유지한
  채 "업데이트 중"을 보여주는 동작이 없습니다. 상태는 화면에 들어온 시점에
  고정됩니다.
- **직원 호출이 no-op입니다.** B1 `ext/Sheet`가 아직 없습니다.
- QR 재스캔으로 세션에 재참여하는 경로(§5.1)가 없습니다. 현재 S08은 S07을
  거쳐야만 도달할 수 있고, 새로고침하면 주문 내역이 사라집니다
  (`localStorage` 영속화 §6.2 미구현).
- E5(주방 거절) 경로는 범위 밖입니다.
